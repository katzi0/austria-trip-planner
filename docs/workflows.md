# Workflows

Operational recipes. For the data shape itself, see [`data-model.md`](./data-model.md).

---

## Add a day

**Easy path:** open http://localhost:3000/edit → scroll to the day list → click "+ הוסף יום" → fill in fields → "שמור". In local dev any passphrase works.

**Claude path:** run `/add-day` and follow the prompts.

**Manual path:** edit `.data/austria-2026.json`, insert a new `Day` object (see [`data-model.md`](./data-model.md#day)) at the position that keeps `days[]` in date order, increment `n` for any later days you didn't touch (or just append and let `n` be max+1 — the UI sorts by `n`).

Always run `/check-data` after.

---

## Add a region (base)

1. Add the entry to `trip.regions` with a fresh key (lowercase, no spaces).
2. Append the key to `trip.baseOrder`.
3. Add at least one `Day` whose `base` is that key — orphans render fine but the ribbon shows an empty region.

If you do this in [`lib/seed.ts`](../lib/seed.ts), also keep the same field order as the existing regions for readability.

---

## Move days between bases

Change `day.base` to a different region key. That's it — the region polygons re-compute (in `components/Map.tsx`) from member days, and the ribbon counts update. If the move leaves the source region with zero days, decide whether to delete the region or leave it as an empty placeholder.

---

## Schema change

Touching the shape of `Day`, `Region`, or `Trip` requires updates in lockstep:

1. **`lib/trip-schema.ts`** — change the Zod schema and the inferred TypeScript type.
2. **`lib/seed.ts`** — update `SEED_TRIP` so every existing entry satisfies the new shape.
3. **`.data/austria-2026.json`** — if you have a live local trip, edit it too. Easiest: delete the file and let the next read re-seed.
4. **`app/edit/page.tsx`** — update `emptyDay` / `emptyRegion` factories (so the editor's "+ הוסף" button produces valid objects) **and** the form fields.
5. **Renderers** — search-grep for the renamed/removed field across `components/`. Renderers that read removed fields will crash.
6. **DB** — if you've already deployed: the `trips.data` JSONB column doesn't enforce the shape, so old rows survive a deploy, but `readTrip` will throw on the first GET. Run a one-shot migration via the seed script or a `tsx` snippet.
7. `npm run typecheck` — must pass before commit.

## Update PWA icons

The current `public/icons/icon-*.png` are solid-color placeholders generated by `scripts/gen-icons.ts`. To use real art:

- Produce three PNGs: `icon-192.png` (192×192, transparent OK), `icon-512.png` (512×512), `icon-maskable-512.png` (512×512, with ≥20% safe-zone padding for Android maskable).
- Drop them into `public/icons/`. The manifest references are stable; no other change needed.
- Hard-reload (or unregister the SW in DevTools) to see the new icons after a production build.

## Switch map style

Default style: OpenFreeMap "liberty" — `https://tiles.openfreemap.org/styles/liberty`.

Set `NEXT_PUBLIC_MAP_STYLE_URL` to any MapLibre-compatible style JSON URL to override. Free options:

| Style | URL | Look |
|---|---|---|
| OpenFreeMap Liberty | `https://tiles.openfreemap.org/styles/liberty` | Mapbox-Outdoors-ish (default) |
| OpenFreeMap Positron | `https://tiles.openfreemap.org/styles/positron` | Light, minimal (Carto-ish) |
| OpenFreeMap Bright | `https://tiles.openfreemap.org/styles/bright` | OSM-style colorful |
| OpenFreeMap 3D | `https://tiles.openfreemap.org/styles/3d` | With 3D buildings |
| Stadia AlidadeSmooth | `https://tiles.stadiamaps.com/styles/alidade_smooth.json` | (free tier, no key for dev) |
| MapTiler | `https://api.maptiler.com/maps/<style>/style.json?key=<key>` | (free tier, requires key) |

Restart the dev server after changing env.

## Reset local trip data

Delete `.data/austria-2026.json`. The next GET to `/api/trip` re-seeds from `SEED_TRIP` and writes a fresh file.

```bash
rm .data/austria-2026.json
curl -s http://localhost:3000/api/trip > /dev/null   # triggers re-seed
```

## Backup / export

Until the JSON import/export GUI is built (deferred to v2):

```bash
# backup
curl -s http://localhost:3000/api/trip | jq . > backups/trip-$(date +%F).json

# restore
curl -s -X PATCH http://localhost:3000/api/trip \
  -H "Content-Type: application/json" \
  -d "$(jq -n --slurpfile t backups/trip-2026-06-06.json '{passphrase:"dev",trip:$t[0]}')"
```

In prod replace `"dev"` with your `EDIT_PASSPHRASE`.

## Deploy to Vercel

First-time:

```bash
# 1. Link the project
vercel link

# 2. In the Vercel dashboard: Storage → Create → Postgres → link to project
# 3. Pull env vars locally
vercel env pull .env.local

# 4. Add the edit gate
echo 'EDIT_PASSPHRASE=<choose-a-long-passphrase>' >> .env.local
# also set it in Vercel project env (vercel env add EDIT_PASSPHRASE production)

# 5. Seed the DB from the in-code SEED_TRIP (or from a backup)
npm run seed

# 6. Push — Vercel auto-deploys main on push
git push
```

Subsequent deploys are just `git push`. The DB persists; edits via `/edit` go straight to Postgres.

## Run typecheck

The only static-check gate. No lint, no tests.

```bash
npm run typecheck
```

Or run `/verify` in Claude to also include a dev-server smoke probe.
